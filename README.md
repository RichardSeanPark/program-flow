# Program Flow — KRX / NXT

키움증권 **읽기 전용** `ka90008` REST API로 종목별 프로그램 매수·매도·순매수 시각별 스냅샷을 수집하는 독립 웹앱입니다. `kium`이나 `kium2`를 import하거나 수정하지 않습니다. KRX 종목코드는 6자리, NXT는 같은 코드에 `_NX`를 붙여 조회합니다. 응답의 `stex_tp`도 확인해 타 시장 데이터 혼입을 막습니다.

## 다운로드

- [처음 사용하는 분을 위한 이미지 설명서입니다.](docs/windows-beginner.md)
- [Windows 설치 파일 및 소스 다운로드](https://github.com/RichardSeanPark/program-flow/releases/latest)
- Windows 10/11 64비트용 `ProgramFlow-Setup-0.2.6-x64.exe`를 내려받아 설치하세요.
- 설치하지 않고 사용하려면 `ProgramFlow-Portable-0.2.6-x64.zip`을 **모두 압축 해제**한 뒤 `ProgramFlow.exe`를 실행하세요. ZIP 안에서 바로 실행하거나 EXE 하나만 복사하지 마세요.
- 키움 REST API 사용 신청과 본인 App Key/Secret, 등록 IP 설정이 필요합니다. 계정 정보는 배포 파일에 포함되지 않습니다.

## 화면 디자인 (0.2.6)

나눔고딕을 앱에 포함해 별도 폰트 설치나 외부 폰트 서버 없이 표시합니다. 밝은 화면과 어두운 화면은 오른쪽 위 테마 버튼으로 전환하며 선택은 브라우저에 저장됩니다. 세션 카드의 작은 그래프는 실제 저장된 데이터만 사용합니다. 차트에 포인터를 올리면 시각과 순매수 누적값을 확인할 수 있습니다. 좁은 화면에서는 차트 축과 검색·설정 화면이 화면 너비에 맞춰 조정됩니다. 설정 창은 키보드 Tab으로 이동하고 Escape로 닫을 수 있습니다.

## Windows 설치·실행 (일반 사용자)

`ProgramFlow-Setup-0.2.6-x64.exe`를 Windows 64비트 PC에서 더블클릭해 설치하고, 시작 메뉴의 **Program Flow**를 실행하세요. Python·WSL·명령줄은 필요하지 않습니다. 브라우저 화면만 열리며 별도의 실행 상태 창은 표시하지 않습니다. 작업표시줄 알림 영역의 **Program Flow** 아이콘 메뉴에서 **프로그램 화면 열기** 또는 **종료**를 선택할 수 있습니다. 실행 중 바로가기를 다시 누르면 열린 프로그램 화면을 다시 엽니다. 설치는 현재 Windows 사용자 계정에만 적용되고 관리자 권한이 필요하지 않습니다.

첫 실행에는 기존 WSL의 저장 키·조회 내역이 옮겨지지 않습니다. 브라우저 화면의 **키움 API 가이드**를 보고 본인 키를 설정에서 등록하세요. 종목명 포함 검색과 차트는 기존 웹앱과 같고 키움 연결이 있어야 실제 데이터가 조회됩니다. Windows 저장 위치는 `%LOCALAPPDATA%\ProgramFlow`(데이터베이스와 `master.key`)입니다. **배포용 설치 파일·소스는 공유할 수 있지만, 이 개인 데이터 폴더와 본인 API 키는 공유하지 마세요.** 제거해도 사용자 데이터는 보존되므로 완전 삭제가 필요할 때는 백업 후 해당 폴더를 직접 삭제하세요. 기존 WSL 개발 서버(`localhost:8765`)와 Windows 설치본(`127.0.0.1`의 빈 포트)은 서로 다른 저장소·브라우저 쿠키를 사용합니다.

### EXE와 같은 위치의 소스 실행

```text
ProgramFlow/
  ProgramFlow.exe
  program_flow/       # 실제 실행하는 Python 소스와 화면 파일
    windows_launcher.py
    app.py
    static/
  _internal/          # Python 런타임과 의존 라이브러리
  LICENSE
  README.md
```

EXE는 자신의 폴더에 있는 `program_flow`를 읽어 실행합니다. 소스가 없거나 불완전하면 오류를 표시하며 내장 구버전으로 대체 실행하지 않습니다. 앱을 알림 영역에서 완전히 종료한 뒤 이 소스를 수정하고 EXE를 다시 실행하면 수정 내용이 적용됩니다. Python 소스·화면 변경에는 재빌드가 필요 없지만 새 외부 라이브러리 추가나 EXE 부트스트랩 변경에는 재빌드가 필요합니다. 설치 업데이트는 소스를 덮어쓸 수 있으므로 수정본은 별도로 백업하세요.

배포용 설치 파일은 아직 코드 서명되지 않았습니다. Windows 보안 경고가 나오면 출처를 확인하고 실행하세요. 회사 외부 배포·키움 계정 사용 정책 확인은 별도입니다.

### Windows 개발 PC에서 설치 파일 만들기

Windows 64비트 빌드 PC에 Python 3.13과 Inno Setup 6을 설치한 다음 저장소에서 `C:\Python313\python.exe build_windows.py`를 실행합니다. 빌드 도구는 `.build/`에만 설치되며 `release/`의 설치 파일에는 Python 런타임과 앱 화면이 함께 들어갑니다. 이 단계의 Python·Inno Setup 설치는 **제작 PC만** 필요합니다. 최종 사용자 PC에는 둘 다 설치하지 않습니다. 설치본 확인은 깨끗한 임시 데이터 디렉터리에서 `ProgramFlow.exe --smoke-test --data-dir <빈 폴더>`로 수행하며 기존 키·데이터를 건드리지 않습니다. 백그라운드 수집·브라우저 종료·재시작 검증은 별도의 `ProgramFlow.exe --collector-smoke-test --data-dir <다른 빈 폴더>`에서 **모의 응답만** 사용합니다. 실제 60초 간격을 두 차례 관측하려면 `ProgramFlow.exe --collector-minute-test --data-dir <또 다른 빈 폴더>`를 사용합니다(약 3분 소요, 모의 응답만 사용). 두 수집 시험 모두 명시적 빈 폴더가 없으면 실행되지 않습니다. 이 시험은 실제 키움 계정이나 실거래 자료를 확인한 것이 아닙니다.

## WSL2에서 실행

Windows 경로 `D:\work\program`, WSL 경로 `/mnt/d/work/program`:

```bash
cd /mnt/d/work/program
bash run.sh
```

첫 실행은 `uv`로 Python 가상환경과 의존성을 **WSL ext4 홈 디렉터리**에 설치합니다. Windows 브라우저에서 `http://localhost:8765`를 여세요. 서버를 종료하려면 실행 터미널에서 Ctrl+C. 서버는 기본적으로 로컬에서만 접속 가능합니다.

계정 로그인·초대 코드는 없습니다. 첫 접속 때 브라우저마다 고유한 HttpOnly/SameSite=Strict 쿠키를 발급합니다. 키움 신청부터 등록까지 그림 안내는 앱 상단 **키움 API 가이드** 또는 `http://localhost:8765/static/kiwoom-rest-guide.html`에서 열 수 있습니다. 열린 키움 REST API 연결 창에 각자의 App Key/Secret을 등록하세요. 등록 시 키움 토큰 발급을 확인하며, 사용자별 자격증명은 Fernet 암호화 후 WSL ext4 SQLite에 저장합니다. 암호화 마스터 키는 `~/.local/share/program-flow-web/master.key`에 0600으로 생성됩니다. 이 디렉터리를 삭제하면 저장 데이터를 잃을 수 있으니 백업 시 **DB와 master.key를 함께** 안전하게 보관하십시오. 브라우저에는 API 키를 저장하지 않습니다. 대신 브라우저 프로필의 쿠키가 유일한 접근 수단입니다. 쿠키 삭제·시크릿 모드 종료·프로필 교체·1년간 미방문 시 이전 키와 데이터에 다시 접근할 수 없습니다. 같은 브라우저 프로필을 쓰는 사람들은 키와 데이터를 공유하므로 각자 별도 프로필/기기를 사용해야 합니다. 키움 앱의 허용 IP에는 이 서버의 **고정 외부 IP**가 필요합니다.

## 연결 복구와 로그

첫 연결 또는 조회 실패 시 브라우저가 5초부터 최대 30초 간격으로 자동 재연결합니다. 키움이 유효하지 않은 토큰을 거부하면 저장된 키로 토큰을 새로 발급하고 같은 조회를 한 번 다시 실행합니다. 이후 실패도 화면에서 자동 재시도하며, 저장된 데이터는 유지합니다. 처음 데이터를 받기 전에는 대기 애니메이션을 표시하고 시장별 저장이 완료되는 대로 화면에 반영합니다. KRX와 NXT 중 한 시장이 실패해도 다른 시장 수집은 계속합니다. 연속조회 중 통신 중단·일시적 서버 오류·요청 제한이 발생하면 해당 페이지만 최대 3번 재시도합니다. 연속조회는 최대 200페이지까지 처리하며, 불완전한 조회 결과는 저장하지 않습니다.

Windows 로그 위치는 `%LOCALAPPDATA%\ProgramFlow\logs\program-flow.log`입니다. 실행·토큰 갱신 결과·종목·시장·조회 페이지 진행·저장 건수·소요 시간·오류를 기록합니다. 로그는 파일당 약 2MB, 이전 파일 3개까지 순환 보관합니다. API 키·시크릿·접근 토큰 원문은 로그에 기록하지 않습니다.

## 키움 인증 만료 처리

- 키움이 안내하는 **24시간 만료 대상은 접근 토큰**입니다. 앱 키와 시크릿 키로 토큰을 발급받고, 응답의 `expires_dt`(한국시간)를 기준으로 만료 5분 전부터 재발급합니다. 서버 시작 시 저장된 각 브라우저 프로필의 토큰을 발급하고, 브라우저 연결 직후 및 API 조회 직전에 다시 확인합니다. 서버 재시작 시 메모리의 기존 토큰은 사라지므로 새 토큰을 발급합니다.
- 토큰 발급 실패 시 저장된 조회 데이터는 유지하고 화면에 오류를 표시합니다. 앱 키·시크릿 키 자체가 무효/만료되어 새 값이 필요하면 프로그램이 키움에서 새 키를 자동 생성할 수 없습니다. 키움 사이트에서 새 키를 발급받아 앱 **설정**에서 직접 재등록하세요. 등록 IP나 네트워크 오류도 토큰 발급을 막을 수 있습니다. 실제 자격증명을 이용한 재발급은 자동화 테스트에서 실행하지 않았습니다.

## 데이터 처리

- 화면의 **종목명** 칸에 이름의 일부를 입력하면 해당 글자가 포함된 종목을 최대 20개 제안합니다. 원하는 이름(동명이면 옆의 6자리 코드까지 확인)을 클릭하거나 방향키·Enter로 선택하면 그 코드를 수집 대상으로 저장하고 자동 수집합니다. 선택하지 않은 입력은 수집하지 않습니다. 첫 화면의 `삼성전자`도 공식 이름과 코드 확인 후 자동으로 시작합니다. 후보가 20개보다 많다면 검색어를 더 입력하세요.
- 후보와 정확한 이름 확인은 등록된 키움 API 키로 공식 `ka10099` 종목목록(KOSPI·KOSDAQ)의 연속조회 결과를 이용합니다. 종목 목록은 브라우저 프로필별로 최대 6시간 동안 재사용하며 키를 변경·삭제하면 지웁니다. 이름이 없거나 기본값의 정확한 이름에 여러 코드가 있으면 추측하지 않고 오류를 표시합니다. 종목명 검색에도 정상적인 키움 토큰과 네트워크가 필요합니다.
- 선택한 종목은 브라우저 프로필별로 저장합니다. 설치본이 알림 영역에서 실행되는 동안 서버가 브라우저 탭이 숨겨지거나 닫혀도 **오늘 날짜**의 KRX·NXT를 약 60초 간격으로 자동 수집합니다. 알림 영역 메뉴에서 프로그램을 종료하거나 PC가 절전/종료되면 수집이 멈춥니다. 다른 종목을 선택하면 해당 종목으로 변경되고, 다음 실행 때 마지막 종목을 복원합니다. 과거 거래일을 선택하면 그 날짜를 한 번 자동 조회하며, 백그라운드 정기 수집 대상은 계속 오늘 날짜입니다.
- 열린 브라우저는 60초마다 서버에 저장된 데이터를 읽어 그래프를 다시 그리고, 숨겨진 탭이 다시 보이면 즉시 다시 읽습니다. 브라우저/운영체제가 숨겨진 탭의 타이머를 늦추거나 일시 정지할 수 있어 **숨겨진 탭의 화면이 정확히 매분 다시 그려지는 것은 보장하지 않습니다**. 서버 수집과 화면 표시 시각은 다를 수 있습니다.
- KRX와 NXT는 각각 조회하며 연속조회 페이지를 모두 받은 후에만 시장별로 저장합니다. 한 시장 요청이 실패하면 그 시장을 동기화 완료로 표시하지 않고 화면에 오류를 표시합니다.
- 같은 분에 여러 시각이 있으면 마지막 관측값만 보관합니다. 과거 날짜는 성공 후 재조회하지 않으며, 당일 두 시장은 약 60초마다 조회합니다(시장별 조회 시차를 감안해 59초 미만의 중복 요청을 건너뜁니다). 수동 조회·수집 버튼은 없습니다.
- 값의 단위는 키움의 **백만원 → 원**으로 정규화합니다. 빈 분을 0으로 생성하지 않습니다. NXT 오후 계산에 필요한 15:30 이전 기준 관측값이 없으면 누적값을 `—`로 표시합니다.
- 날짜별 완전한 분봉이 실제 API에서 모두 제공되는지는 **실제 계정·종목·거래일 응답으로 별도 검증 필요**합니다. REST 응답의 관측 시각을 저장하는 것이며, 연속적인 매분 체결 데이터를 보장한다는 뜻은 아닙니다.
- 브라우저별 식별 쿠키는 HttpOnly/SameSite=Strict, 변경 요청은 같은 Origin만 허용합니다. 프로필별 DB 행을 분리하며 주문/계좌 API는 없습니다.

테스트는 외부 API를 모킹하며 실제 키움을 호출하지 않습니다.

## 공개 서비스 전 필수 조건

현재 WSL 실행 설정은 **로컬 개발용**입니다. 설치본도 로컬 1인 사용용이며 인터넷 공개 서비스가 아닙니다. 타인에게 웹 서비스를 제공하려면 HTTPS 역방향 프록시, 고정 송신 IP, 익명 세션 생성·API 호출의 IP별 제한, 백업, 로그/알림, 운영 보안 점검이 필요합니다. `PROGRAM_FLOW_SECURE_COOKIE=1`을 설정하고 HTTPS 프록시의 Host/Origin 및 전달 헤더를 올바르게 구성하세요. 키움 약관에서 제3자 키 보관 및 시세 재제공 허용 범위도 확인해야 합니다. WSL 개발 데이터는 WSL ext4에, Windows 설치본 데이터는 각 사용자 `%LOCALAPPDATA%\ProgramFlow`에 별도로 보관됩니다. PWA 설치는 HTTPS 또는 localhost에서만 지원됩니다.
